# AI 주식투자 에이전트 경쟁 시스템 (모의투자 버전)

메리츠증권(또는 추후 연동되는 증권사) 계좌를 대상으로, 서로 다른 투자 방법론을 쓰는
10개의 에이전트가 정해진 예산으로 경쟁하며 주간 단위로 성과를 겨루고, 매주 가장 성과가
좋은 에이전트의 전략을 공유받아 각자의 방식대로 발전시켜 나가는 시스템입니다.

## 현재 상태 (2026-09-16 기준)

- 핵심 프레임워크(데이터 어댑터, 10개 전략 에이전트, 가상 포트폴리오, 주간 스코어링,
  전략 공유/진화 로직)를 구현하고 가상 데이터로 전체 파이프라인을 검증 완료.
- **실데이터 연동은 아직 안 됨**: 이 클라우드 실행 환경은 조직 네트워크 정책상
  naver/yahoo/증권사 API 등 외부 도메인에 직접 접근이 차단되어 있습니다
  (허용된 도메인: pypi, npm, Anthropic API 등뿐). 실제 시세/거시경제 데이터 및
  메리츠증권 Open API 연동을 위해서는 아래 "다음 단계" 중 하나가 필요합니다.

## 폴더 구조

```
stock-agents/
├── core/
│   ├── data.py        # 데이터 제공자: Synthetic(검증용) / FDR(국내) / YFinance(해외) / Meritz(자리표시자)
│   ├── indicators.py  # SMA/EMA/RSI/MACD/볼린저밴드 등 기술적 지표
│   ├── portfolio.py   # 가상 포트폴리오(현금/보유/체결/평가금액)
│   ├── agents.py       # 10개 전략 에이전트
│   ├── scoring.py      # 일별 1위에 1점 부여하는 주간 토너먼트
│   ├── evolution.py    # 주간 우승 전략 공유 + 각 에이전트 파라미터 진화
│   └── simulator.py    # 전체 오케스트레이터
├── demo_run.py          # 가상 데이터로 15거래일(3주) 검증 실행 스크립트
└── state/                # 실행 결과(JSON) 저장 위치
```

## 10개 에이전트 (서로 다른 방법론)

| ID | 이름 | 핵심 로직 |
|---|---|---|
| agent01 | 모멘텀 추종 | 최근 N일 수익률 상위 K종목 매수 |
| agent02 | 평균회귀 (RSI) | RSI 과매도 구간 종목 매수 |
| agent03 | 가치투자 근사 | 장기 평균 대비 저평가된 종목 매수 (실 재무데이터 연동 전 근사치) |
| agent04 | 이동평균 크로스 | 골든크로스(단기MA>장기MA) 종목 매수 |
| agent05 | MACD 시그널 | MACD선의 시그널선 상향 돌파 시 매수 |
| agent06 | 거래량 돌파 | 신고가+거래량 급증 동반 돌파 시 매수 |
| agent07 | 거시경제 섹터 로테이션 | 금리/유가 등 매크로 지표로 섹터 비중 조절 |
| agent08 | 변동성 타겟팅 | 변동성 역가중(낮은 변동성에 높은 비중) |
| agent09 | 듀얼 모멘텀 | 절대모멘텀(자체 상승) + 상대모멘텀(동종대비 우위) |
| agent10 | 매수 후 보유 | 전종목 균등비중 매수 후 보유 (벤치마크) |

## 경쟁/진화 규칙 구현 내용

1. **일별**: 10개 에이전트 모두 당일 종가 기준 가상 체결. 당일 수익률이 가장 높은
   에이전트에게 1점 부여 (`core/scoring.py`).
2. **주간(ISO 주 단위)**: 그 주 동안 획득한 점수(및 주간 누적수익률)로 주간 우승 에이전트
   결정. 우승 에이전트의 파라미터(예: 모멘텀 관찰기간, 선정 종목 수 등)를 다른 에이전트들이
   자기 정체성(시그널 종류)은 유지한 채 15%만큼 그 방향으로 소폭 이동. 우승 에이전트 자신도
   지역 최적점 고착을 막기 위해 top_k를 탐험적으로 미세 조정 (`core/evolution.py`).
3. 위 사이클을 반복하며 각 에이전트가 자신만의 방법론 안에서 점진적으로 개선되도록 설계.

## 실행 방법 (가상 데이터로 테스트)

```bash
cd stock-agents
python3 demo_run.py
```

## 진행 상황 업데이트 (2026-09-16)

- claude.ai에서 이 계정은 Team/Enterprise가 아니라 **Admin → Capabilities 네트워크 설정
  메뉴 자체가 없음**을 확인함 (개인 플랜으로 추정). 클라우드 세션과 PC 디바이스 브리지
  셸(device_bash) 모두 동일한 계정 단위 egress 정책의 적용을 받아, 둘 다 naver/yahoo
  등 외부 도메인에 직접 접근이 차단됨을 실제 테스트로 확인함.
- **메리츠증권은 2026-09 기준 개인용 Open API를 아직 제공하지 않음**
  (2026-05 보도 기준 "연내 출시 예정"이었으나 출시 확인 안 됨). 대안으로 RPA(HTS 화면
  자동조작) 방식이 존재하나 Windows 전용·불안정·약관 위반 소지가 있어 비권장.
- → **한국투자증권(KIS, Korea Investment & Securities) Open API로 실계좌 연동 방향을
  전환하기로 결정함.** `core/data.py`에 `KISOpenAPIProvider` 뼈대(skeleton) 추가함
  (아직 실제 HTTP 호출 미구현, 네트워크 접근 확보 후 채워 넣을 예정).

## 다음 단계

1. **KIS 계좌 및 API 키 준비**
   - 한국투자증권 계좌가 없다면 개설
   - [KIS Developers 포털](https://apiportal.koreainvestment.com/)에서 회원가입 → API 신청
   - 실전투자용, 모의투자용 app key/app secret을 각각 발급 (모의투자는 별도 참가신청 필요할 수 있음)
   - 모의투자용 키부터 먼저 발급받아 전달하는 것을 권장 (실전투자 키는 이후 단계에서)
2. **네트워크 접근 문제 해결** — 아래 중 하나 선택:
   - (A) Team 플랜으로 업그레이드해 Admin → Capabilities에서 KIS API 도메인
     (`openapi.koreainvestment.com`, `openapivts.koreainvestment.com`)을 허용
   - (B) 금융데이터 MCP 커넥터(Alpha Vantage 등)로 시세 데이터만 우선 확보하고,
     주문 실행은 추후 별도 경로 모색
   - (C) 그 외 우회 경로가 없는지 추가 조사
3. **일정 확정** — 국내장(09:00~15:30 KST)과 미국장(22:30~05:00 KST, 서머타임에 따라 변동)
   중 언제 매매 판단을 실행할지, 주간 마감 시점(예: 금요일 장마감 후)을 확정.
4. **리스크 관리 규칙 추가 여부** — 종목당 최대 비중, 일일 손실 한도(서킷브레이커),
   전량 매도 조건 등 안전장치를 어느 수준으로 둘지 결정.
