# AI 주식투자 에이전트 경쟁 시스템 (모의투자)

한국투자증권(KIS) Open API를 통해 실제 국내+해외 시세로, 서로 다른 투자 방법론을 쓰는
10개의 에이전트가 정해진 예산(에이전트당 1,000만원)으로 모의투자 경쟁을 벌이는 시스템입니다.
매일 아침 GitHub Actions가 자동으로 하루치 매매를 실행하고, 주간 단위로 가장 성과가 좋은
에이전트의 전략을 다른 에이전트들이 참고해 각자의 방식대로 발전시켜 나갑니다(진화).

## 현재 상태 (2026-09-16 기준)

- **완전 자동화 운영 중.** GitHub Actions가 평일 KST 08:00에 자동 실행되어 KIS 모의투자
  API로 실시간 국내(005930 등 5종목)+해외(AAPL 등 5종목) 시세를 받아 10개 에이전트가
  매매를 결정하고, 결과 상태(`state/live_state.json`)를 저장소에 자동 커밋합니다.
  사람이 노트북을 켜거나 터미널을 열 필요가 전혀 없습니다.
- GitHub 저장소: `donghyunyou-svg/stock-agents-tournament`
- 실행 검증 완료: 실제 KIS API로 2회 이상 성공 실행, 10개 종목 전체 데이터 정상 수신 확인.
- 예산: 에이전트당 1,000만원 미만 (모의투자), 투자유니버스: 국내 5종목 + 해외 5종목.

## 폴더 구조

```
stock-agents/
├── core/
│   ├── data.py        # 데이터 제공자: KISOpenAPIProvider(실사용) / Synthetic(검증용) / FDR·YFinance(미사용, 네트워크 제약)
│   ├── indicators.py  # SMA/EMA/RSI/MACD/볼린저밴드 등 기술적 지표
│   ├── portfolio.py   # 가상 포트폴리오(현금/보유/체결/평가금액/고점대비낙폭)
│   ├── agents.py       # 10개 전략 에이전트 + 공통 리스크 관리(비중 상한)
│   ├── scoring.py      # 일별 1위에 1점 부여하는 주간 토너먼트
│   ├── evolution.py    # 주간 우승 전략 공유 + 각 에이전트 파라미터 진화
│   └── simulator.py    # 전체 오케스트레이터 + 공통 서킷브레이커(낙폭 제한)
├── run_daily.py          # GitHub Actions가 매일 실행하는 진입점(실계좌 KIS 연동)
├── demo_run.py           # 가상 데이터로 15거래일(3주) 검증 실행 스크립트
├── .github/workflows/daily_trading.yml  # 매일 자동 실행 스케줄
└── state/                # 실행 결과(JSON) 저장 위치 (live_state.json = 실운영 상태)
```

## 10개 에이전트 (서로 다른 방법론)

| ID | 이름 | 핵심 로직 |
|---|---|---|
| agent01 | 모멘텀 추종 | 단기(5일)/중기(20일)/장기(60일) 모멘텀을 0.2/0.3/0.5 가중 평균해 상위 K종목 매수 |
| agent02 | 평균회귀 (RSI) | RSI 과매도 구간 종목 매수 |
| agent03 | 가치투자 | 국내 종목은 실제 PER/PBR(KIS 조회)로, 해외/조회실패 종목은 장기평균 대비 할인폭으로 저평가 종목 매수 |
| agent04 | 이동평균 크로스 | 골든크로스(단기MA>장기MA) 종목 매수 |
| agent05 | MACD 시그널 | MACD선의 시그널선 상향 돌파 시 매수 |
| agent06 | 거래량 돌파 | 신고가+거래량 급증 동반 돌파 시 매수 |
| agent07 | 거시경제 섹터 로테이션 | 금리/유가 등 매크로 지표로 섹터 비중 조절 (데이터 미확보 시 노출 절반으로 안전하게 축소) |
| agent08 | 변동성 타겟팅 | 변동성 역가중(낮은 변동성에 높은 비중) |
| agent09 | 듀얼 모멘텀 | 절대모멘텀(90일 자체 상승) + 확인모멘텀(5일 단기 상승) 둘 다 양(+)인 종목만 매수 |
| agent10 | 매수 후 보유 | 전종목 균등비중 매수 후 보유 (벤치마크) |

## 성과 극대화를 위해 모든 에이전트에 공통 적용한 안전장치/개선사항

사용자 요청("성과를 극대화하기 위해 에이전트들이 고려/사용/수행해야 할 것들")에 따라
아래 항목들을 전략과 무관하게 모든 에이전트에 공통 적용했습니다.

1. **종목당 비중 상한 (35%)** — 아무리 좋은 신호라도 한 종목에 몰빵하면 변동성이
   커지므로, 개별 종목 비중을 35%로 제한 (`BaseAgent.MAX_POSITION_WEIGHT`).
2. **고점 대비 낙폭 서킷브레이커 (15% / 3거래일 냉각)** — 에이전트별 평가금액이
   역대 최고점 대비 15% 이상 하락하면 즉시 전량 현금화하고 3거래일 동안 신규 매수를
   금지. 하락장에서 살아남는 것이 장기 성과 극대화의 핵심이라는 원칙 (`TournamentSimulator`).
3. **실제 재무데이터(PER/PBR) 연동** — KIS API의 `inquire-price` 엔드포인트로 국내
   종목의 실제 PER/PBR을 매일 조회해 가치투자 에이전트(agent03)에 제공. 조회 실패/해외
   종목은 기존 가격 기반 근사치로 자동 폴백.
4. **멀티 타임프레임 모멘텀** — 모멘텀 에이전트(agent01)는 단일 기간이 아닌 단기/중기/
   장기 신호를 가중 평균해 단기 노이즈에 덜 흔들리도록 개선.
5. **듀얼 확인 신호** — 듀얼 모멘텀 에이전트(agent09)는 장기 추세와 단기 확인 신호가
   둘 다 양(+)일 때만 진입해 추세 반전 초기 손실을 줄임.
6. **매크로 데이터 부재 시 안전 모드** — 거시경제 로테이션 에이전트(agent07)는 실제
   금리/유가 데이터가 없으면 추측값을 쓰는 대신 노출을 절반으로 낮춰 보수적으로 운용
   (현재 KIS의 금리/유가/환율 지수 코드는 검증되지 않아 실데이터 미연동 상태 — 아래
   "다음 단계" 참고).
7. **개별 종목 조회 실패 시 부분 진행** — 특정 종목 시세/재무데이터 조회가 실패해도
   전체 사이클이 중단되지 않고 해당 종목만 건너뛰도록 방어적으로 구현 (KIS 모의투자
   서버의 초당 요청 제한에 대응해 재시도/backoff 로직도 포함).

## 경쟁/진화 규칙 구현 내용

1. **일별**: 10개 에이전트 모두 당일 종가 기준 가상 체결. 당일 수익률이 가장 높은
   에이전트에게 1점 부여 (`core/scoring.py`).
2. **주간(ISO 주 단위)**: 그 주 동안 획득한 점수(및 주간 누적수익률)로 주간 우승 에이전트
   결정. 우승 에이전트의 파라미터(예: 관찰기간, 선정 종목 수 등)를 다른 에이전트들이
   자기 정체성(시그널 종류)은 유지한 채 15%만큼 그 방향으로 소폭 이동. 우승 에이전트 자신도
   지역 최적점 고착을 막기 위해 top_k를 탐험적으로 미세 조정 (`core/evolution.py`).
3. 위 사이클을 반복하며 각 에이전트가 자신만의 방법론 안에서 점진적으로 개선되도록 설계.

## 실행 방법

- **가상 데이터로 로컬 테스트**: `python3 demo_run.py`
- **실계좌(모의투자) 실행**: GitHub Actions가 평일 KST 08:00에 자동 실행 (수동 실행도
  저장소 Actions 탭 → Daily Trading Cycle → Run workflow로 가능).

## 다음 단계 / 미해결 사항

1. **저장소 공개 여부 결정** — 매일 저녁 8:30 성과 리포트를 인증 없이 안정적으로
   만들려면 저장소를 공개로 전환하거나(코드/모의투자 수치만 있어 민감정보 없음),
   비공개 유지 시 별도 토큰 기반 접근 방식이 필요함. 사용자 결정 대기 중.
2. **실 매크로 데이터 연동** — 금리(미국채 10년물)/유가/환율/VIX 등 실제 거시지표를
   KIS API로 받아오려면 정확한 종목/지수 코드 확인이 필요함. 추측으로 잘못된 코드를
   쓰면 운영 중 조용히 실패할 위험이 있어, 검증 전까지는 agent07을 안전 모드로 유지함.
3. **실전투자 전환 여부** — 현재는 모의투자(paper trading)로만 운영 중. 일정 기간
   검증 후 실전 전환 여부는 사용자 판단.
